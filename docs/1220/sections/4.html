4. Amortized analysis

4.1. Example: Union Find

We motivate amortized analysis by exploring efficient implementations for the disjoint-set data structure.

Disjoint-set/Union-Find:
  • Maintain a collection 𝒮︀={𝑆𝑖} of pairwise disjoint sets.
  • Support following operations:
    1. Make-Set(𝑥)
    2. Union(𝑥,𝑦)
    3. Find-Set(𝑥)

Example applications include tasks involving equivalence classes.

  • Maintain connected components of a graph as we add edges. Cycle detection.
  • Kruskal’s algorithm for Minimum spanning tree

Approach 1 (Linked List)

  • Consider representing each set with a linked list, where the first element in each set “represents” the set and each element has an additional pointer to the first element, so that Find-Set runs in Θ(1). Naively, union step is worst case Θ(𝑁), and 𝑁 unions starting from singleton sets can take Θ(𝑁2) time.
  • Idea: copy smaller set into larger. A single union is still worst case Θ(𝑁). We claim the cost of all unions is 𝑂(𝑁log𝑁). This is because no element is copied more than log𝑁 times (check). Hence in an “average” sense, each union operation is 𝑂(log𝑁). If we let 𝑀 be the total number of operations, including the make sets and unions, then the time complexity is 𝑂(𝑀+𝑁log𝑁)=𝑂(𝑀log𝑁)

4.2. [REVIEW] Amortized Analysis Methods

We want to analyze the worst case running time of a sequence of operations. Here are a few techniques:

  1. Aggregate: compute total cost of 𝑘 ops and divide by 𝑘.
  2. Accounting: charge fictitious amortized cost for each op so that earlier cheap ops pay for larger expensive ops.
    1. For example, assign a cost of 3 for appending elements to a dynamic array. The cost of resizing is zero.

  3. Physics-inspired Potential: Assign a potential Φ𝑖 after the 𝑖th op. The amortized cost 𝑐̂𝑖of the 𝑖th op is

    𝑐̂𝑖=𝑐𝑖+Φ𝑖−Φ𝑖−1 (6)

    so that after 𝑛 operations the total amortized cost is

    ∑𝑖=1𝑛⏟real cost+Φ𝑛−Φ0. (7)
    • Choose Φ such that for all sequences Φ𝑛−Φ0 is positive, hence the amortized cost is an upper bound to the real cost.
    • For example, the amortized cost for a dynamic array is 2𝑛−𝑚+1 where 𝑚 is the capacity. The amortized cost of an add operation (with or without doulbing) is 3.

Approach 2 (Forest-of-trees algorithm)

  • Let each set be a tree, not necessarily binary or balanced, with upward pointers representing the set.
  • Make-Set is Θ(1), Find-Set is O(height), and Union is now Θ(1).
  • The worst case behavior sucks: running 𝑀 Find-Sets is worst case Θ(𝑀𝑁).

Two heuristics for improving runtime:

  1. Union by rank: Assign each element a rank starting at 0. Union(x,y): if rank x ≤ rank y, make the root of x a child of the root of y. Also, if rank x = rank y, increment rank y.
    • Invariants: rank strictly increases as you go up the tree.
    • 𝑥 has rank 𝑟 implies it has at least 2𝑟 elements in its subrtee.
    • Hence the height of any tree is ≤log𝑁, where the worst case corresponds to a binary search tree. Hence Find-Set operates in worst case 𝑂(log𝑁) time.
  2. Path compression: after Find-Set, make all elements on the path point to the root (reduce the height of the tree).

    • Claim. 𝑁 Make-sets followed by 𝑀 ops runs in 𝑂(𝑀log𝑁) worst case time.

      Proof

      It suffices to show that each operation has amrotized cost 𝑂(log𝑁). Define

      Φ(DS)=∑𝑥∈DSlog|𝑥| (8)

      where |𝑥| is the number of elements in 𝑥’s subtree. SInce the potential starts out at zero and ends positive, clearly Φ𝑛−Φ0 is positive.

      The amortized cost of Make-Set is 1+0=0. The amortized cost of Union(x,y) is

      1+log(|𝑥|+|𝑦|)−log(|𝑦|)=𝑂(log𝑁). (9)

      Let the path to the root from 𝑥0=𝑥 be 𝑥0,…,𝑥𝑚,𝑟. The amortized cost of Find-Set(x) is

      1+∑𝑖=1𝑚(1+log(1−|𝑥𝑖−1||𝑥𝑛|))=𝑂(log𝑛) (10)

      by a clever counting argument.

      □
