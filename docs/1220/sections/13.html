13. Sublinear algorithms

13.1. Definition

  • Classical algorithms: read the input and compute answer
  • Online algorithms: provide answer after each read piece
  • Streaming algorithms: same as online but only remember a tiny amount of history
  • Sublinear algorithms: compute an answer in much less time than is needed to read the input.
    • We settle for “approximately correct” answers. There are two notions of this:
      1. Optimization: Return answer that is within 𝛼 of the correct one.
      2. Decision: Always return YES if the input is a YES instance with some false positives for inputs “close” to having the property.

Example 3 (Testing connectedness of a graph). A graph 𝐺 on 𝑛 vertices and maximum degree 𝑑 is 𝜀-close to connected if adding less than 𝜀𝑑𝑛 edges can make 𝐺 connected.

Suppose given a node 𝑣 we can query its adjacency list for its ≤𝑑 neighbors. Given 𝜀∈(0,1) with 𝜀≫1d𝑛, write an 𝑂(𝑛) algorithm that outputs YES if 𝐺 is connected and NO with probability ≥34 if 𝐺 is not ε-close to being connected. If 𝐺 is not connected but ε-close to being connected, then either output is valid.

Remark. 3/4 is arbitrary. We can boost by running multiple times and returning NO if and only at least 1 NO output.

Solution

Intuitively, non 𝜀-close to connected graphs have many small connected compnents, so our randomized algorithm should exploit this. In particular if 𝐺 is not 𝜀-close to connected, then

  1. 𝐺 has >𝜀𝑑𝑛 connected components
  2. At least half of those components have <2𝜀𝑑 nodes.

The algorithm repeats this step 𝑐𝜀𝑑 times: pick a random node and BFS until you find ≥2𝜀𝑑 nodes and stop or <2𝜀𝑑 nodes and return NO. Return YES at the end. The runtime for each iteration is (2𝜀𝑑𝑑), hence the total runtime is O(1𝜀2𝑑)∈𝑂(𝑛) by assumption. Correctness requires the inequality (1−1𝑥)𝑥≤1𝑒.

Example 4 (Testing sortedness of a list). [REVIEW] A list of 𝑛 numbers 𝜀-close to sorted if we can delete ≤𝜀𝑛 elements and get a sorted list. Given 𝜀∈(0,1) sastisfying 1𝜀≪𝑛, write an 𝑂(1𝜀log𝑛) algorithm that outputs YES if 𝐴 is sorted and NO with probability at least 34 if 𝐴 is not 𝜀-close to sorted.
Solution

First note that an algorithm that checks consecutive pairs requires 𝑂(𝑛) time. Consider the input 1,3,5,7,2,4,6,8 for example. Similarly an algorithm that checks arbitrary pairs runs into the counterexample: 2,1,4,3,6,5,8,7.

We need a way to count the number of elements we need to remove in the optimal solution. Call these elements “not good.” Refer to a node 𝑖 as “good” if binary searching for 𝑥𝑖 works. Then if 𝑖<𝑗 and 𝑖,𝑗 are both good, then 𝑥𝑖<𝑥𝑗. Hence if we remove all list elements that are not good, the remaining list is sorted, giving an upper bound on how many elements need to be deleted. If the list is 𝜀-far from being sorted, then the number of not good indices is necessarily >𝜀𝑛. Hence the probability of finding one is at least 1/𝜀. Hence the algorithm is to pick a random node and check if it is not good, and output NO. At the end, output YES.

□

Remark. Both assumptions about 𝜀 for the past too problems are not necessary for correctness but are there to talk about the “interesting” regime where the algorithm is sublinear. Indeed we can think of counterexamples e.g. 2 large CCs or removing one element that are impossible to find in sublinear time. For example, if there is one bad element, the probability you hit it is at most 𝑞𝑛 where 𝑞 is the number of queries. So an algorithm that succeeds with probability ≥34 on every input needs 𝑞=Ω(𝑛).
