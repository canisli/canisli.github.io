    1. Introduction

    1.1. Markov Decision Processes

    We begin with a model of the environment.

    Definition 1. An MDP is a 6-tuple (𝒮︀,𝒜︀,𝑅,𝑃,𝜌0,𝛾) where 𝒮︀ is the set of valid states, 𝒜︀ is the set of valid actions, 𝑅 is the reward function, 𝑃 is the transition probability function, and 𝜌0 is the starting state distribution. We have a discount factor 𝛾∈(0,1) as well.

    Given a fully-known MDP, we want to maximize expected long-run reward. When the action space is discrete, we parameterize a categorical policy which outputs logits. For a continuous action space we parameterize a diagonal action policy which outputs a mean and diagonal (log)covariance matrix.

    1.2. DP Approach to MDPs

    This section constructively proves the following result:

    Theorem 1. Consider an infinite-horizon discounted MDP. Then there exists an optimal policy that is stationary and deterministic, and it can be chosen greedily with respect to the optimal value functieon.

    1.3. Bridge from MDP to RL

    We assume the environment is an MDP with state space 𝒮︀ and action space 𝒜︀.

    • Unlike dynamic programming, the agent does not have access to the transition kernel 𝑃 or reward function 𝑟, and does not require an explicit enumeration of 𝒮︀; instead, it observes sampled transitions generated by interacting with the environment under its current policy.
    • The action space 𝒜︀ is assumed to be known.
    • The agent need not know the full set of reachable states.

    In partially observed settings, 𝒮︀ may be latent, and the agent instead conditions on observations 𝑜𝑡 (and possibly history ℎ𝑡) that is treated as approximately Markov.

    The objective is to learn a policy 𝜋 that maximizes expected return.

    1.4. Taxonomy of RL Algorithms

    There’s also gradient-free methods like evolution strategies and genetic algorithms. See below.

    1.4.1. Model-free RL

    Two main approaches: policy optimization learns 𝜋𝜃(𝑎|𝑠) and Q-learning learns 𝑄𝜃(𝑠,𝑎). The first is optimized on-policy, meaning each update only uses data collected while acting to the most recent version of the policy. The latter is off-policy. The corresponding policy is given by 𝑎(𝑠)=argmax𝑎𝑄𝜃(𝑠,𝑎).

    Q-Learning tends to be less stable as its optimizing for a self-consistency equation but is more sample efficient since its off-policy. It turns out that the two techniques are equivalent under some circumstances.

    1.4.2. Model-based RL

    Assume access to a model accurate enough to outperform the current policy over a limited horizon at decision time. Or perhaps we have the exact model with for example chess.

    Model-based loop

    1. Collect data
    2. Update model
    3. Plan using model
    4. Produced an improved action
    5. Update policy
    6. Repeat
    • Pure planning: compute a plan using model predictive control and execute the first step of the plan and recompute the plan each step
    • Expert iteration: explicit learn 𝜋𝜃(𝑎|𝑠). Use a planning algorithm to produce an action which is better than what the policy alone would have produced. Update the policy to match the expert.f
    • Data augmentation for model-free methods: use model-free algorithm but augment real experiences with fictitious ones / only use fictitious ones.
    • Embedding Planning Loops into Policies

    2. Value-based methods

    2.1. Q-learning

    Q-learning learns 𝑄(𝑠,𝑎) as a lookup table while DQN parameterizes it using a neural network. Perform gradient descent to update weights for each new experience. To avoid ccatastrophic forgetting, we save experiences into a replay buffer instead of online learning.

    3. Policy gradient methods

    For convergence, we consider either finite-horizon undiscounted return or infinite-horizon discounted return.

    A policy induces a distribution over entire trajectories:

    𝜏=(𝑠0,𝑎0,𝑠1,𝑎1,…)𝑝𝜋(𝜏)=𝜌0(𝑠0)∏𝑡𝜋(𝑎𝑡|𝑠𝑡)𝑃(𝑠𝑡+1|𝑠𝑡,𝑎𝑡) (6)

    The objective is

    𝐽(𝜃)=𝔼𝜏∼𝜋𝜃[𝑅(𝜏)] (7)

    We will construct a surrogate objective whose gradient equals the policy gradient, i.e. the gradient of 𝐽(𝜃)=𝔼𝜏∼𝜋𝜃[𝑅(𝜏)].

    To Monte Carlo estimate the gradient, we can gradient descent on the loss function (treating the rewards as constants)

    ℒ︀=−1|𝐷|∑𝜏∈𝐷∑𝑡=0𝑇log𝜋𝜃(𝑎𝑡|𝑠𝑡)Φ𝑡 (13)

    Warning: ℒ︀ has the same gradient as −𝐽(𝜃) but cannot be interpretted as expected return.

    Empirically, setting Φ𝑡 to the reward-to-go function ∑𝑡′=𝑡𝑇𝑟𝑡′ reduces variance compared to if we used the total reward. Intuitively, we don’t want early actions to get rewearded for things from much later, or late actions to get credit for earlier rewards. This is exactly what REINFORCE, the original Monte Carlo policy-gradient algorithm from 1992, does.

    REINFORCE
    1. Sample episodes and store transition
    2. For each episode 𝜏
      1. For each timestep 𝑡,

        1. Compute the reward-to-go

          𝐺𝑡=∑𝑡′=𝑡𝑇𝛾𝑡′−𝑡𝑟𝑡 (14)
        2. Update 𝜃←𝜃+𝛼∇𝜃log𝜋𝜃(𝑎𝑡|𝑠𝑡)𝐺𝑡

    Remark. During training we sample moves according to the policy. During evaluation it is standard to greedy sample instead of sampling stochastically.

    3.2.1. Notes on implementation

    • The rewards should be treated as constant and not differentiable (the environment is not differentiable). Use torch.stack() to accumulate the log probabilities while retaining requires_grad=True.

    • For sampling from the policy, use

      dist = Categorical(logits=logits)
logp = dist.log_prob(a)

      Reasoning: PyTorch computes log_softmax internally in a stable way. You avoid forming tiny probabilities explicitly. This is the standard trick in classification too.

    • To reduce the variance, subtract the returns to go from their mean. If we don’t do this, then all gradients push probabilities up since all 𝐺𝑡 are positive. Instead we want to estimate advantages:

      def train(self, optimizer: torch.optim.Optimizer,
            num_episodes=10, T=100, γ=0.99):
    model = self.model

    model.train()
    for _ in tqdm(range(num_episodes)):
        loss = 0.0
        moves, rewards, logps, _ = self.run_episode(T)
        
        # Returns to go
        returns = []
        for t in range(T):
            G_t = 0.0
            for k in range(T - t):
                G_t += (γ ** k) * rewards[t + k]
            returns.append(G_t)
        returns = torch.tensor(returns, dtype=torch.float32)
        
        # REINFORCE loss
        loss = - (logps * (returns-returns.mean())).mean()

        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
    • Normalize inputs to −1 and 1. I was passing in the x, y position on the board, but I should divide by the half-width.
    • Returns to go: Mathematically the returns should be counted from the beginning of the episode, not 𝑡. I.e. ∑𝑡′=𝑡𝑘𝛾𝑡′𝑟𝑡′=𝛾𝑡𝐺𝑡 instead of 𝐺𝑡=∑𝑡′=𝑡𝑘𝛾𝑡′−𝑡𝑟𝑡′. REINFORCE drops the extra 𝛾𝑡 factor anyway. Intuitively this prevents the algorithm from focusing on early decisions, and empirically it works out to be a feature not a bug.
