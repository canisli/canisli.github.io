1. Introduction

1.1. Markov Decision Processes

We begin with a model of the environment.

Definition 1. An MDP is a 6-tuple (𝒮︀,𝒜︀,𝑅,𝑃,𝜌0,𝛾) where 𝒮︀ is the set of valid states, 𝒜︀ is the set of valid actions, 𝑅 is the reward function, 𝑃 is the transition probability function, and 𝜌0 is the starting state distribution. We have a discount factor 𝛾∈(0,1) as well.

Given a fully-known MDP, we want to maximize expected long-run reward. When the action space is discrete, we parameterize a categorical policy which outputs logits. For a continuous action space we parameterize a diagonal action policy which outputs a mean and diagonal (log)covariance matrix.

1.3. Bridge from MDP to RL

We assume the environment is an MDP with state space 𝒮︀ and action space 𝒜︀.

  • Unlike dynamic programming, the agent does not have access to the transition kernel 𝑃 or reward function 𝑟, and does not require an explicit enumeration of 𝒮︀; instead, it observes sampled transitions generated by interacting with the environment under its current policy.
  • The action space 𝒜︀ is assumed to be known.
  • The agent need not know the full set of reachable states.

In partially observed settings, 𝒮︀ may be latent, and the agent instead conditions on observations 𝑜𝑡 (and possibly history ℎ𝑡) that is treated as approximately Markov.

The objective is to learn a policy 𝜋 that maximizes expected return.

1.4. Taxonomy of RL Algorithms

There’s also gradient-free methods like evolution strategies and genetic algorithms. See below.

1.4.1. Model-free RL

Two main approaches: policy optimization learns 𝜋𝜃(𝑎|𝑠) and Q-learning learns 𝑄𝜃(𝑠,𝑎). The first is optimized on-policy, meaning each update only uses data collected while acting to the most recent version of the policy. The latter is off-policy. The corresponding policy is given by 𝑎(𝑠)=argmax𝑎𝑄𝜃(𝑠,𝑎).

Q-Learning tends to be less stable as its optimizing for a self-consistency equation but is more sample efficient since its off-policy. It turns out that the two techniques are equivalent under some circumstances.

1.4.2. Model-based RL

Assume access to a model accurate enough to outperform the current policy over a limited horizon at decision time. Or perhaps we have the exact model with for example chess.

Model-based loop

  1. Collect data
  2. Update model
  3. Plan using model
  4. Produced an improved action
  5. Update policy
  6. Repeat
  • Pure planning: compute a plan using model predictive control and execute the first step of the plan and recompute the plan each step
  • Expert iteration: explicit learn 𝜋𝜃(𝑎|𝑠). Use a planning algorithm to produce an action which is better than what the policy alone would have produced. Update the policy to match the expert.f
  • Data augmentation for model-free methods: use model-free algorithm but augment real experiences with fictitious ones / only use fictitious ones.
