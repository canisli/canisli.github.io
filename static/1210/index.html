    2. Asymptotic Time Complexity

    Let 𝑅(𝐱) refer to the number of operations executed by an algorithm as a function of the input 𝐱 of size 𝑛. Define the worst case time complexity as

    𝑇(𝑛)=max|𝐱|=𝑛𝑅(𝐱). (1)

    Definition 1 (Asymptotic Time Complexity). We say that:

    1. 𝑇(𝑛)∈O(𝑔(𝑛)) if there exists constants 𝐶 and 𝑛0 such that for every 𝑛>𝑛0, 𝑇(𝑛)≤𝐶𝑔(𝑛). Equivalently, for every 𝑛>𝑛0, for every input of length 𝑛, 𝑅(𝐱)≤𝑐𝑔(𝑛).
    2. 𝑇(𝑛)∈Ω(𝑔(𝑛)) if there exists constants 𝐶 and 𝑛0 such that for every 𝑛>𝑛0, 𝑇(𝑛)≥𝐶𝑔(𝑛). Equivalently, for every 𝑛>𝑛0, there exists a single input 𝐱 of length 𝑛 such that 𝑅(𝐱)≥𝐶𝑔(𝑛) (due to max).
    3. 𝑇(𝑛)∈Θ(𝑔(𝑛)) if it belongs in both O(𝑔(𝑛)) and Ω(𝑔(𝑛)).

    Say the operations have amortized cost 𝑇 if any sequence of 𝑚 operations takes total time at most 𝑚𝑇.

    Note that our usage of O differs from that of power series expansions, where we consider the behavior for small, continuous 𝑥. If 𝑓(𝑥)=𝑎0+𝑎1𝑥+O(𝑥2), then we say |𝑓(𝑥)−(𝑎0+𝑎1𝑥)≤𝐶𝑥2 for sufficiently small 𝑥.

    There are three techniques to prove the asymptotic time complexity of a recurrence relation: (1) substitution method, (2) drawing a recurrence tree, and (3) Master Theorem.

    Example 1 (Substitution Method). Prove that 𝑇(𝑛)=𝑇(𝑛/2)+O(1). The idea is to guess a solution and prove it inductively.

    I claim 𝑇(𝑛)∈O(log𝑛),𝑖.𝑒. there exists 𝑐 such that for large 𝑛, 𝑇(𝑛)≤𝑐log𝑛. Take 𝑐 such that 𝑇(𝑛)−𝑇(𝑛/2)≤𝑐. We will use strong induction. The base case is 𝑇(𝑛)=O(1), which is true.

    𝑇(𝑛)=𝑇(𝑛/2)+O(1)≤𝑐log𝑛/2+𝑐≤𝑐log𝑛 (2)

    proving the inductive step.

    Theorem 1 (Master Theorem). Suppose 𝑇(𝑛) satisifes a recurrence of the form 𝑇(𝑛)=𝑎𝑇(𝑛/𝑏)+𝑓(𝑛). Let 𝑐crit=log𝑏𝑎.
    1. If 𝑓(𝑛)=O(𝑛𝑐) for 𝑐<𝑐crit, then 𝑇(𝑛)=Θ(𝑛𝑐crit)
    2. If 𝑓(𝑛)=Θ(𝑛𝑐crit)(log𝑛)𝑘) for 𝑘≥0, then 𝑇(𝑛)=Θ(𝑛𝑐crit(log𝑛)𝑘+1).
    3. If 𝑓(𝑛)=Ω(𝑛𝑐) for 𝑐>𝑐crit, and the “regularity condition” holds (𝑎𝑓(𝑛/𝑏)≤𝑘𝑓(𝑛)) for some 𝑘<1), then 𝑇(𝑛)=Θ(𝑓(𝑛)).
    Proof
    𝑇(𝑛)=𝑓(𝑛)+𝑎𝑓(𝑛/𝑏)+𝑎2𝑓(𝑛/𝑏2)+…+𝑎𝑑𝑓(𝑛/𝑑2) where 𝑑=log𝑏𝑛. Write it out as a a geometric series and consider the leading term to get the three cases.
    • In case 3, the geometric series grows slower than 𝑓(𝑛) itself, thus the time complexity is dominated by the 𝑓(𝑛) term.

    □

    Example 2. Karatsuba algorithm for multiplying two numbers of 𝑛 digits satisifes the recurrence relation 𝑇(𝑛)=3𝑇(𝑛/2)+Θ(𝑛𝑐). Thus the time complexity is O(𝑛log23)≈O(𝑛1.58).

    Note. A for-loop of size 𝑛 in which we add 𝑛 digit integers is O(64𝑛) rather O(𝑛log𝑛) since integers are stored as 64 bits.

    Later we will consider expected and amortized time complexities.

    4. Sets and hashing

    A set is an abstract data type that supports storing items having unique keys (e.g. item x has key x.key). It supports the following operations:

    Proposition 1. Given a set of 𝑛 items, any comparison search algorithm is Ω(log𝑛).
    Proof
    Model the algorithm as a decision tree with at least 𝑛 nodes. The running time is related to the height, which follows Ω(log𝑛).

    □

    • Moving beyond comparison search, we can implement find(k) faster than O(log𝑛) . The idea is represent the set with a direct access array, where each index is a key value and we put 𝑥 at index 𝑥.key. This has a large memory overhead, Ω(𝑢), and is not feasible if 𝑢, the number set of possible keys is large.
      • For example, if keys are ten-letter names, a Direct Access Array that allocates one bit per name requires 2610bits ≈ 17.6 TB space.

    • If 𝑛≪𝑢, we can map keys to a smaller range of size 𝑚 and use a smaller DAA of size 𝑚. This is the idea of hashing, and the hash function is

      ℎ(𝑘):{0,…,𝑢−1}→{0,…,𝑚−1}. (3)
      The smaller DAA is called a hash table.
    • If 𝑚=O(𝑛), we basically have an array of size 𝑛; other operations like find_min and find_max are O(𝑛)!
    • Since 𝑚≪𝑢, no hash function is injective by pigeonhole. We address collisions with two methods:
      1. chaining: Each item of the hashtable is a pointer to another data structure supporting dynamic set interface, like a LinkedList.
      2. open addressing: store somewhere else in the array.
    • A good hash function should be fast and uniform. A good basic choice is ℎ(𝑘)=(𝑘mod𝑚) where 𝑚 is a large prime far from powers of 2 and 10.
      • We can study the expected time complexity under SUHA (simple uniform hashing assumptino).

    4.1. Faster sorting

    Direct Access Array Sort ⇒ Counting sort O(𝑛+𝑢) ⇒ Tuple Sort O(𝑘(𝑛+𝑢)), e.g. Radix sort

    Tuple sort: If keys are represented as tuples of size 𝑘. We have two techniques based on the order we sort the tuples in:

    1. (Least to most significant) Apply counting sort stably lexicographically 𝑘 times for a time complexity of O(𝑘(𝑛+𝑢)).
    2. Sort by most significant key and then sort equivalent elements by remaining keys. Worst case is also O(𝑘(𝑛+𝑢)) when all the keys are the same except for in the least significant digit.

    Radix sort: If the keys are in a larger range, like 𝑢<𝑛2, we can represent each key in its base 𝑛 representation, e.g. 𝑘=𝑎𝑛+𝑏. Then we can use tuple sort in O(log𝑛𝑢𝑛)=O(𝑛) when 𝑢<𝑛𝑐.

    6. AVL Trees

    Representing a set or sequence with a binary tree, depending on what we key. In AVL sequence we don’t key by index rather we let subtree augmentations maintain the structure.

    Idea. Use augmentation to store things like height and size so we can refer to them in O(1). This will make AVL trees possible.

    DFS Algorithm for balancing a tree

    • Check if left subtree is balanced, if not balance it
    • Check if right subtree is balanced, if not balance it.
    • Balance the current node.

    We can rebalance using O(1) rotation operations. In particular, rotations are defined as follows:

    • Right Rotate 𝑦
      • Given a subtree rooted at node y, where x is y’s left child:
        • x becomes the new root.
        • y becomes the right child of x.
        • x’s original right child is assigned to y’s left child.
                    y             x
               / \           / \
              x   C   →    A   y
             / \               / \
            A   B             B   C
    • Left Rotate 𝑦
      • Given a subtree rooted at node x, where y is x’s right child:
        • y becomes the new root.
        • x becomes the left child of y.
        • y’s original left child is assigned to x’s right child.
                    x             y
               / \           / \
              A   y   →    x   C
                 / \       / \
                B   C     A   B

    If we insert a node no further rebalancing is required. If we delete a node the rebalancing may propagate upwards: Example

         O
    / \
   N   1
        /\
      N  B (N-1)

Originaly let $B$ take the form
        b
      / \
N-3    2
         / \
   N-3 N-4

delete on the bottom right branch

        b
      / \
N-3    2
         / \
   N-3 N-5

Rebalancing at 2 makes this tree have height $n-2$, requiring us to rebalance at 1.

            return

            visit(neighbor)
      finishing_order.append(v)

    Definition 3. A topological order of a graph 𝐺=(𝑉,𝐸) is an ordering on the vertices such for every edge (𝑢,𝑣)∈𝐸, 𝑢 appears before 𝑣 in the ordering.
    Proposition 3. A directed graph admits a toplogical ordering if and only if it is a DAG.

    Topological Sort

    1. Let the finishing order be the order in which a Full DFS finishes visiting each vertex in 𝐺.
    2. Output the vertices in reverse finishing order.

    Correctness
    It suffices to show that for every edge (𝑢,𝑣)∈𝐸, 𝑢 is ordered before 𝑣, i.e. the visit to 𝑣 finishes before visiting 𝑢. We have two cases:

    • If 𝑢 is visited before 𝑣, then the 𝑣 is finished before 𝑢 by the recursive nature of DFS.
    • If 𝑣 is visited before 𝑢, then 𝑢 is never visited in 𝑣’s exploration otherwise there would be cycle connecting 𝑢 and 𝑣. Hence 𝑣 finishes before 𝑢.

    Runtime
    Linear

    There exist multiple topological orderings.

    We can use topological sort for cycle detection in linear time by using a hash table to check if for each edge 𝑣 is before 𝑢 in the topoligical sort. Another way is to just check in DFS if a node is ever visited twice (have to keep track of the ancestors from the source node. Another way is to just use Kosaraju’s algorithm and check for a nontrivial SCC.

    9. Single-source shortest path (SSSP)

    We are interested in solving the SSSP problem for graphs that may involve negative weights and cycles.

    It is too slow to keep track of all the shortest paths. Using the optimal subproblem property, it suffices to keep track of a predecessor array (updated during each relaxation). At the end can compute paths recursively using the predecessor array.

    9.1. BFS

    For an unweighted graph, we can simply BFS since each the 𝑖th iteration finds all nodes of distance 𝑖. This is pretty obvious, and the proof is in lecture 10.

    9.2. DAG SP

    Suppose we have a graph that is a DAG. Let 𝑠 denote the source node, and 𝛿(𝑣) denote the distance of the shortest path from 𝑠 to 𝑣 (∞ it does not exist).

    Lemma 1 (Useful properties of paths).
    1. Subpaths of shortest paths are also shortest paths.(Optimal Subproblem Property)
    2. If there is an edge from 𝑢 to 𝑣, 𝛿(𝑣)≤𝛿(𝑢)+𝑤(𝑢,𝑣).(Triange inequality)

    The triangle inequality motivates us to define the following operation:

    Definition 4 (Edge relaxation). Suppose there is an edge from 𝑢 to 𝑣. We can relax this edge by updating

    𝑑(𝑣)=min(𝑑(𝑣),𝑑(𝑢)+𝑤(𝑢,𝑣)). (5)
    Lemma 2 (Path Relaxation Lemma). Suppose 𝑠=𝑣0,𝑣1,…,𝑣𝑘=𝑡 is a shortest path. If (𝑣0,𝑣1),(𝑣1,𝑣2),…,(𝑣𝑘−1,𝑣𝑘) have been relaxed in order, then (regardless of any relaxations performed in between) 𝑑(𝑡)=𝛿(𝑡).
    Proof

    Proceed by induction on the length of the path.

    • Base case: A path of length zero trivially holds.
    • Inductive step: Suppose the property holds for all shortest paths of length 𝑘−1. Then, by the optimal subproblem property, at the time (𝑣𝑘−1,𝑣𝑘) is relaxed we have 𝑑(𝑣𝑘−1)=𝛿(𝑣𝑘−1). Thus after relaxing the edge (𝑣𝑘−1,𝑣𝑘), we have 𝑑(𝑣𝑘)=𝛿(𝑣𝑘) by hypothesis.

    □

    DAG SP Algorithm

    1. Run Full DFS to obtain a topological ordering of the nodes.
    2. Relax the edges in toplogical order.

    Proof of correctness
    Follows immediately from Lemma 2. In particular, the edges in the shortest path will be relaxed in a topological order, ensuring that the lemma applies.

    Runtime
    The time complexity is linear: Θ(|𝑉|+|𝐸|)

    9.3. Bellman-Ford

    DAG SP breaks down on cyclic graphs since they don’t admit a toplogical order. However, if the graph has only positive nodes then all cycles are positive and we can solve the problem in linear time with Kosaraju!

    Let’s try to find a more robust algorithm.

    Definition 5. A simple path is a path that does not contain a cycle.
    Proposition 4.
    1. If a shortest 𝑠−𝑡 path exists, then all shortest 𝑠−𝑡 paths with fewest edges are simple.
    2. Every simple path has at most |𝑉|−1 edges.
    3. Every simple path has at most |𝐸| edges
    4. If a shortest path exists, then such path has at most 𝑁≔min(|𝑉|−1,|𝐸|) edges.
    Proof
    1. In order for a shortest path to exist there must be no relevant negative cycles. Thus any nonsimple paths involve only positive cycles and can be reduced in length to simple paths. We include the “fewest edges” condition to address cycles of weight zero.
    (2) and (3) both follow from the pidgeonhole principle. (1,2,3) together imply (4).

    □

    As a subproblem, let’s first try to find the shortest paths to all nodes assuming there exist shortest paths.

    Naive Bellman-Ford Algorithm

    1. Construct a new DAG 𝐺′ based on 𝑁+1 copies of the original graph 𝐺, with edges from (𝑢𝑖,𝑣𝑖+1) of weight 𝑤(𝑢,𝑣) and edges (𝑣𝑖,𝑣𝑖+1) of weight 0.
      • Note this new graph is acyclic regardless of the orginal graph.
    2. Run DAG SP on 𝐺′ from 𝑠0, and output 𝛿(𝑣)=𝛿(𝑠0,𝑣𝑁) (the node in the last graph).

    Proof of Correctness First we show that there is a duality between paths in 𝐺 and paths in 𝐺′.

    Lemma 3.
    1. If 𝜋 is a path from 𝑠 to 𝑡 in 𝐺 with at most 𝑁 edges, then there is a path 𝜋′ from 𝑠0 to 𝑡𝑁 in 𝐺′ of the same weight.
    2. Similarly, if 𝜋′is a path from 𝑠0 to 𝑡𝑁, then there is a path 𝜋 with at most 𝑁 edges from 𝑠 to 𝑡 in 𝐺 of the same length.
    Proof
    1. If the 𝑖th edge in 𝜋 is (𝑢,𝑣), then include in 𝜋′ the edge (𝑢𝑖−1,𝑣𝑖). For remaining edges, include (𝑡𝑖−1,𝑡𝑖) to account for paths shorter than 𝑁.
    2. Remove all subscripts and zero weight self-loops from 𝜋′.

    □

    • By the above two claims, 𝛿(𝑠0,𝑣𝑁) is the length of a shortest ≤𝑁 edge path from 𝑠 to 𝑣.
    • By Proposition 4, the shortest path has length at most 𝑁, implying 𝛿(𝑣)=𝛿(𝑠0,𝑣𝑁)

    Runtime
    G’ has Θ(𝑁|𝑉|) vertices and Θ(𝑁|𝐸|) edges. Thus the construction of 𝐺′ and DAG SP is Θ(𝑁(|𝑉|+|𝐸|))=Θ(|𝑉‖𝐸|). Our total time complexity is Θ(|𝑉‖𝐸|).

    Now let’s tackle the problem of negative cycles, causing shortest paths to not exist (𝑑=−∞) for some nodes.

    We can detect a cycle in following manner: Take our answer 𝛿(𝑣𝑁), and compare it with what we get if we were to duplicate 𝐺 once more and obtain 𝛿(𝑣𝑁+1). If they are not the same, then 𝑣 is involved in a negative cycle, and there exists a negative cycle. This is formalized by the following lemma:

    Lemma 4 (Negative Cycle Detection).
    1. If 𝑣0,𝑣1,…,𝑣𝑘=𝑣0 is a negative cycle reachable from 𝑠, then there exists 𝑖 such that 𝛿(𝑣𝑁+1𝑖)≠𝛿(𝑣𝑁𝑖).
    2. Conversely, if 𝛿(𝑣𝑖𝑁+1)≠𝛿(𝑣𝑖𝑁), then 𝑣 is involved in a negative cycle.
    Proof
    1. We chose 𝑁 such that a path of length 𝑁+1 is able to fully traverse any cycle reachable from 𝑆. The lecture notes has a rigorous mathematical proof.
    2. By Proposition 4, the shortest path, if exists, has length 𝑁. 𝛿(𝑣𝑖𝑁+1)≠𝛿(𝑣𝑖𝑁) implies that the shortest path does not exist.

    □

    Bellman-Ford with Negative Cycle detection

    1. Construct a DAG 𝐺′ with 𝑁+2 instead of 𝑁+1 copies.
    2. Proceed like with Naive Bellman-Ford.
    3. For all 𝑣 such that 𝛿(𝑣𝑁+1)≠𝛿(𝑣𝑁), DFS from 𝑣 in the original graph and for all reachable vertices, set 𝛿(𝑣)=−∞. (Stop if we reach a node that already got set to −∞).
    4. For the remaining, set 𝛿(𝑣)=𝛿(𝑣𝑁).

    Correctness
    Lemma 4 shows that we have correctly identified all nodes whose shortest paths do not exist. For the remaining nodes, Naive Bellman-Ford works undisturbed.

    Runtime
    Still Θ(|𝑉‖𝐸|). The DFS step with early stopping iterates at most over the entire graph.

    As presented, Bellman-Ford uses Θ(|𝑉‖𝐸|) space. [TODO] However, we can generate 𝐺′ lazily so that we only ever store two copies of 𝐺 at once.

    We can compute paths recursively using the predecessor array. For each relaxation, update the predecessor of a node accordingly.

    Equivalent implemenations:

    1. Since max length of a cycle is |𝑉|, construct a cycle length something like 2𝑁 and run naive Bellman ford, comparing the distance at N and 2N. This will work on all nodes whose shortest path does not exist.
    2. Even simpler, we can just relax all the edges 𝑁 times. Correctness follows from the following lemma:
      1. After 𝑖 repetitions of the loop, if 𝑑(𝑢)≠∞, it is equal to the length of some path from 𝑠 to 𝑢.
      2. After 𝑖 repetitions of the loop, if there is a path from 𝑠 to 𝑢 with at most 𝑖 edges, 𝑑(𝑢) is at most the length of the shortest path from 𝑠 to 𝑢 with at most 𝑖 edges.

    9.4. Dijkstra

    Assume our graph has nonnegative weights. This is more stringent condition than the absence of negative cycles, and is required for the proof to work. It’s easy to come up with a counterexample.

    Dijkstra’s Algorithm

    1. Start from s, take closest node, remove it, and relax its outgoing edges. Remove the next closest node and keep going by maintaining a priority queue.

    Correctness
    Proceed by strong induction on (the number) of vertices removed from 𝑄.

    • We say that relaxation is safe since 𝑑(𝑣) is always either ∞ or the weight of a path to 𝑣. Hence 𝛿(𝑣)≤𝑑(𝑣) at all times.
    • Base case: Obvious for 𝑠 itself / first edge.

    • Inductive step: Suppose we are removing 𝑣 from 𝑄, and that for all vertices 𝑢 already removed from 𝑄, 𝑑(𝑢)=𝛿(𝑣).

      • Let 𝜋 be a shortest path from 𝑠 to 𝑣, and let 𝑦 be the first vertex in 𝜋 still in 𝑄 (possibly 𝑣 itself), and let 𝑥 be its predecessor (already removed by definition of 𝑦).

    Just doing a SSSP algorithm 𝑉 times is pretty good, since the output has size O(𝑉2).     10.1. Task 1: Solve APSP or output ⟂ if there is a negative cycle

    Idea 1. Make edge weights non-negative while preserving shortest paths. For vertex 𝑣, add 𝜙(𝑣) to all outgoing edges and subtract 𝜙(𝑣) from all incoming edges.
    Proposition 5. Shortest paths are preserved under the above reweighting.
    Proof
    We get a telescoping sequence that a constant offset 𝑤(𝜋′)=𝑤(𝜋)+𝜙(𝑣0)−𝜙(𝑣𝑘). Every path changes by the same amount so any shortest path will still be shortest.

    □

    How do we find such path? We need to find a function such that 𝑤(𝑢,𝑣)+𝜙(𝑢)−𝜙(𝑣)≥0 for every edge (𝑢,𝑣). This looks exactly like the triangle equality, and so the condition will be satsified if we let 𝜙(𝑣)=𝛿(𝑠,𝑣) for some 𝑠 where all 𝑣∈𝑉 are reachable from 𝑠. For many graphs this may not be the case, but we can cleverly fix this:

    Idea 2. Create a supernode 𝑠 with a directed 0-weight edge to every 𝑣∈𝑉, so that every node is reachable from 𝑠.
    Proposition 6. 𝐺𝑠 (𝐺 with supernode 𝑠 added) has a negative cycle if and only if 𝐺 does.

    Thus Bellman-Ford on 𝐺𝑠 will tell us if there exists a negative cycle in 𝐺. If there doesn’t, we can use the above transformation, run normal Dijstrka, and transform back:

    𝛿(𝑢,𝑣)=𝛿′(𝑢,𝑣)−𝜙(𝑢)+𝜙(𝑣) (7)

    where 𝜙(𝑛)=𝛿(𝑠,𝑛).

    The total time complexity is O(𝑉2log𝑉+𝑉𝐸). It is dominated by the step of running Dijkstra 𝑉 times.

    10.2. Task 2: Solve APSP for pairs of nodes that are not connected by a negative cycle.

    Suppose 𝐺 has negative cycles but we want to output the shortest paths that still exist.

    1. Compute SCCs of 𝐺 and the condensation graph 𝐻.
    2. Use Bellman Ford on each SCC to see if it contains a negative cycle. (Summed over all SCCs, this is bounded by O(𝑉𝐸) time complexity)
    3. Make a weighted version of 𝐻 where 𝑤𝐻(𝐴,𝐵)=−1 if 𝐴 or 𝐵 contains a negative cycle, and 𝑤𝐻(𝐴,𝐵)=0.
    4. Run APSP on 𝐻 with DAG APSP (running DAG SP on each vertex), and for 𝐴 with a negative cycle, set 𝛿𝐻(𝐴,𝐴)=−1.
    5. Create a graph 𝐺∗ by removing from 𝐺 all SCCs containing negative cycles.
    6. Compute APSP on 𝐺∗ using Task 1.
    7. For all vertices 𝑢,𝑣∈𝑉, let 𝐴,𝐵 be the SCCs of 𝑢,𝑣 respectively.
      1. If 𝛿𝐻(𝐴,𝐵)<0, set 𝛿(𝑢,𝑣)=−∞ (path has negative cycle).
      2. If 𝛿𝐻(𝐴,𝐵)=∞, set 𝛿(𝑢,𝑣)=∞ (nodes are not connected).
      3. Otherwise set 𝛿(𝑢,𝑣)=𝛿∗(𝑢,𝑣).

    Correctness. 𝛿(𝑢,𝑣)=−∞ if and only if 𝑢 can reach 𝑣 via a negative cycle, which occurs if and only if 𝐴 can reach 𝐵 via some SCC with a negative cycle, which occurs if and only if 𝛿𝐻(𝐴,𝐵)<0. We made sure that the 𝛿𝐻(𝐴,𝐴) is handled correctly. Otherwise, the transformation from 𝐺 to 𝐺∗ only removes vertices that no shortest path in 𝐺 can go through, so the shortest path distances in 𝐺∗ match those in 𝐺∗, so correctness follows from correctness of Kosaraju, Bellman-Ford, DAG APSP, and Task 1.

    11. Greedy Algorithms

    11.1. General procedure

    Definition 6. A problem satisfies the Greedy Choice Property (GCP) if there is an optimal solution that contains the greedy choice.
    Template for greedy algorithms
    1. Identify greedy choice
    2. Prove greedy choice property
    3. Identify notion of subproblem
    4. Prove monotonicity: replacing the solution to any subproblem with a different solution to the subproblem which is at least good does not reduce the overall value of the solution. That is, if we are trying to minimize/maximize some objective function that is monotonic in the answer to the subproblem objective function, then we want an optimal solution to the subproblem.

    An example where OSSP doesn’t hold: suppose the longest simple path between 𝑠 and 𝑡 goes through 𝑣. Then the path from 𝑠 to 𝑣 is NOT the longest simplest path. Neither DP nor greedy will work here.

    Theorem 2 (Meta Theorem). The GCP and monotonicity together imply the correctness of a greedy algorithm.
    Proof

    Proceed by strong induction.

    • Let GREEDY be the solution from the greedy algorithm, and let 𝑆 be an optimal solution containing the greedy choice 𝑔 (guaranteed to exist by the GCP).
    • Decompose 𝑆𝐺 into 𝑔 plus the optimal solution GREEDY𝑃 to the subproblem 𝑃 induced by making the greedy choice. The optimality of the greedy algorithm on this subproblem follows from strong induction.
    • Now consider 𝑆 decomposing as 𝑔 plus the solution 𝑆𝑃 to 𝑃. By monotonicity, we can replace 𝑆𝑃 with GREEDY𝑃. Thus the value of greedy is at least the value of 𝑆, which is optimal.

    This proof isn’t rigorous since we haven’t formally defined subproblem or value.

    □

    Remark. Other texts refer to monotonicity as the optimal substructure property: an optimal solution to the problem contains optimal solutions to the sub-problems. OSSP is also invoked in DP proofs.

    Example 3 (Activity Scheduling Problem). Given the start and end times of CPW events, maximize the number of CPW events you can go it.
    Solution


    Algorithm:

    1. Process events sorted by end time in nondecreasing order.
    2. If you can add an event to your schedule, add it.

    Proof of Correctness:

    • Greedy Choice: Include the event 𝐸∗ of earliest end time.
      Proof. Suppose an optimal solution does not contain 𝐸∗ but rather its earliest end time event is 𝐸. Then all the other events must start after 𝐹’s end time and thus after 𝐸’s end time as well. Hence we can replace 𝐹 with 𝐸.
    • Monotononicity: Our subproblem is to chose events that start after 𝐸 ends. We must find an optimal solution 𝑆 to this since our answer is |{𝐸}⊔𝑆|=1+|𝑆|.

    □

    Example 4 (Job Scheduling Problem). Given homework durations and deadlines, minimize the maximum lateness.
    Solution

    Algorithm:

    1. Sort by deadline in nondecreasing order.
    2. Do the task

    Proof of Correctness

    • Greedy Choice: Do the first due task first. Proof. Suppose 𝑇0 is due earlier than 𝑇1 but we do 𝑇1 first before 𝑇0. It suffices to show the two penalty terms decrease. In particular, the penalties go from 𝑡1−𝑑1 and 𝑡1+Δ𝑡+𝑡0−𝑑0 to 𝑡0−𝑑0 and 𝑡1+Δ𝑡𝑡0−𝑑1. Since 𝑑0<𝑑1, the second term in the original penalities is larger than the first. It’s also larger than both of the new penalties. Hence swapping does not increase the penalty.
    • Monotonicity: After doing one task, we can create a subproblem by subtracting 𝑡0 from all their due dates. The total penalty is max(lateness of first,lateness of subproblem), which is monotonic in the answer to the subproblem.

    □

    11.2. Example: Huffman Codes

    Prefix-free variable-length coding

    Given a list of frequencies 𝑓1,…,𝑓𝑛 of 𝑛 symbols, design a prefix free code (PFC) tree with 𝑛 leaves to minimize the length

    𝐿(𝑇)=∑𝑙∈leaves𝑓𝑙⋅𝑑𝑙 (8)

    where 𝑑𝑙 is the depth of the leaf 𝑙.

    Remark. This is different from Shannon’s fixed rate lossless compression theorem.

    Observations

    1. Any optimal tree is a full binary tree (each node has 0 or 2 children).
      • There are multiple possible full binary trees for a fixed number of leaves.
    2. If 𝑓𝑎≤𝑓𝑏 we want 𝑑𝑎≥𝑑𝑏.
    3. We can alternatively formalize the problem as the sum tree problem: let each node be the sum of its two children after assigning 𝑓1,…,𝑓𝑛 to the 𝑛 leaves. Maximize the sum of all nodes except the root. Refer to this as the “Sum-Tree” formalism.

    Huffman’s Algorithm

    We will build the tree bottom up, combining nodes (𝑓1) and (𝑓2) into a new node with value (𝑓1+𝑓2) with (𝑓1) and (𝑓2) as its two children.

    The algorithm is remarkably simple:

    1. Take the two smallest nodes and replace them with a node equal to their sum.
    2. Recurse.
    Proof
    • Observations 1 and 2 clearly imply the GCP property.

    • We prove monotonicity in the following manner: define the subproblem as the set of 𝑛−1 symbols where we’ve replaced 𝑓1 and 𝑓2 with their sum. Let 𝐻′ and 𝑇′ be two solutions to the subproblem. 𝐿(𝐻′)≤𝐿(𝑇′) implies 𝐿(𝐻)=𝐿(𝐻′)+𝑓𝑥+𝑓𝑦≤𝐿(𝑇)=𝐿(𝑇′)+𝑓𝑥+𝑓𝑦.

    □

    Implementation with priority queue has runtime O(𝑛log𝑛).

    def huffman(A):
'''
      input: list of tuples (symbol, frequency)
      output: Huffman tree
'''
      Q = build_min_heap(A)  # (Key, Value)= (Frequency, Symbol)
      for i in range(len(Q) - 1):
            z = Node()
            z.left = x = Q.delete_min()
            z.right = y = Q.delete_min()
            z.freq = x.freq + y.freq

            Q.insert(z)
      
      return Q.delete_min()

    12. Dynamic Programming

    We will be using the SRTBOT framework for describing DP solutions.

    1. Formally define the memo 𝑀 for the different (S)ubproblems. Define its domain or dimensions, and the precise meaning of each entry.
    2. Describe the (R)elationship between the different entries of 𝑀. Show how the entries of 𝑀 can be computed as a function of other entries of 𝑀.
    3. Argue that the dependency graph defined by the relations described in (R) is an acyclic graph. This means that the table 𝑀 can be filled iteratively according to a reverse (T)opological sort of the graph.
    4. Identify the (B)ase cases and show how to initialize them. Base cases are entries in 𝑀 that do not depend on other entries of 𝑀. (These are where the Relate step fails.)
    5. Show how the (O)utput to the original problem depends on the entries of 𝑀 .
    6. Analyze the run(T)ime of the algorithm. Often, this is just the product of the number of entries of 𝑀 times the work done to compute each entry.

    The optimal subproblem property we encountered in graph theory says that solutions subproblems in optimal solutions are optimal as well. Optimal Substructure Property (OSSP) is the converse: optimal solutions to subproblems extend to optimal solutions to the original problems. (Need to show exhaustivity)

    General proof of correctness for DP algorithm:

    1. Any optimal solution for the subproblem defined by A[1:]and 𝐵 is optimal among feasible solutions that do not pick A[0]
    2. Do the same for the other subprolbems.
    3. The above … cases are exhaustive; they partition the set of feasible solutions.

    Use induction on the three recursive calls. By OSSP these three optima can be used to compute global optimum.

    We are interested in which problems have efficient algorithms and why. The main concepts covered are reductions, complexity classes, and pseudopolynomial times.

    • DP interval scheduling problem can be reduced to SSSP with a supernode. [TODO] Constructing the graph can be done in O(𝑛2) though.

    Let’s restrict the discussion to decision problems, where the answer is Yes or No. Informally, we say 𝐴 reduces to 𝐵, denoted 𝐴≤𝐵, if 𝐵 is at least hard as 𝐴. If you could solve 𝐵 efficiently, then you can also solve 𝐴 efficiently.

    Definition 7. For decision problems 𝐴 and 𝐵, we say 𝐴≤𝐵 if given an instance 𝑥 of problem 𝐴, there exists an algorithm that outputs an instance 𝑦 of problem 𝐵 with the same answer.

    For example: 𝐴 is the problem of determining whether there exists a path of length 𝑥 mod 6121 between two vertices, and 𝐵 is the problem of whether there exists a path at all (on the graph with many 6121 copies).

    Definition 8. A complexity class is a set of computation problems. For now we will only consider decision problems.

    • The class 𝖯 is the set of decision problems that can be solved in polynomial time.
    • The class 𝖭𝖯 (nondeterministic polynomial time) is the set of decision problems with a verification procedure 𝑉 that runs in polynomial time, where 𝑉 takes as input a problem instance 𝑥, and a certificate string 𝑐 of length O(poly(𝑛)) and outputs YES or NO. In particular,
      • For every 𝑥 where the answer is YES, there exists a certificate 𝑐 such that 𝑉(𝑥,𝑐) accepts in polynomial time.
      • For every 𝑥 where the answer is NO, for all 𝑐, 𝑉(𝑥,𝑐) rejects.
    • 𝖤𝖷𝖯𝖳𝖨𝖬𝖤 is the class of problems with O(2poly(𝑛) time.
    • 𝖯𝖲𝖯𝖠𝖢𝖤 is the class of algorithms that use poly(𝑛) space.

    We think of 𝖯 as defining efficienct computations since in practice most poly-time algorithms have small exponents.
