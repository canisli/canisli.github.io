2. Number Representation

  • A byte can be represented as 2 hexadecimals. For example, 0xFD = 0b11111011.
  • Examples of bit representations:
    • ASCII: 8-bit representation of uppercase, lowercase, and punctuation
    • Unicode: 8-bit/16-bit/32-bit representation of all symbols including emojis.
    • HTML color codes: 24-bit representations representing RGB.
    • IPv4 and IPv6 are 32-bit and 64-bit representations of device addresses on the internet.

2.1. Signed Integer

  • Strategies to encode signed integers:

    1. We can try to use a bit to represent integer sign, but the overflow pattern is weird2.
    1. One’s complement: A better approach is to represent a negative number by complementing the bits of its positive representation. The leftmost bit is still effectively the sign bit.
    1. Bias encoding: shift by −(2𝑁−1−1)
    • Representing addition is difficult though, since (𝐴+𝐾)+(𝐵+𝐾)=(𝐴+𝐵+𝐾)+𝐾 and not (𝐴+𝐵)+𝐾.
    1. Two’s complement: One’s complement has two ambiguous zeros: 0000 and 1111. Shift all the negative mappings left by one so that 1111 represents −1 and 1000 represents −8.
      • Addition works like adding unsigned bits because adding unsigned bit just works in mod 2𝑁 and this maps the latter half to negatives.
      • This is the standard C23 standard number representation for signed integer.

2.2. Floating Point

  • Fixed point fixes number of digits to left and right of decimal point. Good for domains that prefer very fast computation of values with specific characteristics, e.g. graphics.

  • Scientific notation (in base 2), also called binary normalized form

    • With binary normalized form, mantissa always have a leading one (i.e. scientific notation always has first sig fig as leading one)

    • IEEE 754 single-precision floating point standard (used for C float)

      (−1)𝑠×(1+significand)×2exponent−127

      Assumes implicit 1 instead of directly representing mantissa (to get 24 bits of precision instead of 23). Does not use two’s complement, uses bias-encoding for exponent3.

      Can represent numbers from −3.4e38 to 3.4e38.

    • The double point standard is the same except 1 sign bit, 11 bits with bias −1023, and 52 significand bits. Can represent numbers from −2e308 to 2e308

Additional Properties

  • Special numbers like zero, nan, infinity:

  • Floats have underflow because you can’t represent arbitrarily small numbers. Also, because of the implicit 1 in the normalized mantissa—and zero’s lack thereof—there is a relatively huge difference in step size between 0 and the smallest normalized number compared to the smallest and the second-smallest normalized numbers. We introduce denormalized numbers. When the exponent is zero, remove the implicit leading one. With subnormals the smallest normal value is 2−126 and the smallest subnormal value is 2−149. Without subnormals the smallest normal value is 2−127.

2.2.1. Arithmetic

Steps to add/subtract floats

  1. Denormalize to match exponents
  2. Add significands together
  3. Keep the matched exponent
  4. Normalize, possibly changing the exponent
  5. (Note: If signs differ, just perform a subtract instead.)

Remarks

  • Because floating point is based on powers of 2, it cannot represent most decimal fractions. E.g. 0.1 + 0.2 = 0.30000000000000004.

  • If the exponent difference is larger than the significand width, the smaller operand is shifted entirely out of the working precision.
