# Publication workflow

Make and preview website changes locally first. Push changes or trigger GitHub Pages deployment when the user explicitly asks to publish the reviewed changes.

Verify preview changes through the running Hugo server; if it serves stale configuration, restart it and check the HTTP response instead of rebuilding into its active destination.

When editing or renaming a blog, identify it by its content: the animation research article and the personal life blog are separate pages. Resolve ambiguous references from the user's stated intent rather than the ambient browser URL.
